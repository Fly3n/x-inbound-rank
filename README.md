# X 友（Chrome 插件）

统计谁最常在我的 X 帖子下回复我，给回复者排名，并在时间线和评论区的用户名旁标出名次和次数；榜单里还能看到我在对方帖子下直接回复了几次。数据只存本机，不上传。

- 功能和要求以 [docs/product.md](docs/product.md) 为唯一出处。
- 技术事实、数据模型和维护约束见 [AGENTS.md](AGENTS.md)。
- 当前版本和每版改动见 [CHANGELOG.md](CHANGELOG.md)，弹窗标题旁也显示版本号。

## 设计取舍

- 账号安全最重要，其次才是数据完整、界面轻量和及时性。默认日常**零后台定时主动请求**，靠浏览器旁听自然积累；同一帖子只算一次。
- 所有主动请求均由用户手动触发（「立即更新」或「补历史」），且只在 08:00–24:00、X 页面在前台时执行。
- 当前是维护自用阶段。将来如果决定分发，会先重新评审权限、本机开发桥和风控，不直接沿用维护期配置。

## 安装

1. Chrome 打开 `chrome://extensions`，右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」，选本目录（含 `manifest.json` 的这一层）。
3. 首次安装后，插件会在白天 08:00–24:00 自动刷新当前前台的 x.com 常规页面；后台页面切到前台再补，通知页和夜间不自动刷新，没有自动刷新时再手动刷新一次。

改了代码后在扩展页点刷新。0.25.0 起，插件会在白天自动刷新当前前台还挂着旧内容脚本的 x.com 常规页面，不用再手动逐个刷新；后台页面切到前台再补，通知页、后台页和正常的 X 页面不会被刷新。不需要打包，当前维护自用阶段不上架商店。

## 第一次使用

1. 装好后打开已登录的 x.com；插件会在白天自动刷新各窗口当前前台的旧页面（后台页或跨窗口切回时再补，通知页和夜间不自动刷新；没有自动刷新时手动刷新一次）。在要使用的账号页面点插件图标，再点「为此账号开启」。
2. 开启后无需先做初始化，默认已勾选「旁听收集 [别人回我]」与「旁听收集 [我回别人]」，平时自己在电脑刷 X「通知 / 提及」页、发回复或浏览本人「回复」栏就会自动零请求攒数据；若想补回近期历史，可展开设置页顶部的「补历史」折叠卡，选 **7 天**或 **15 天**并点对应「补历史」。
3. 补历史进行中时看弹窗：显示「进行中，已读 N 页」说明接口和解析对上了；显示红色错误就把提示原样交给维护者，不要反复重试。
4. 打开一条有人回复过你的帖子，看用户名旁是否出现名次和次数标签。
5. 榜单范围最高可选 **3 个月**，数据每天低频积累、本机滚动保存 90 天。

## 使用

### 账号

- 可同时开启多个 X 账号。回复、榜单、设置、排期缓存和诊断日志各自独立；某个账号没有登录页面时，只暂停它自己的任务。
- X 的每个账号有两个名字：页面上的 `@用户名` 可以改；后台的数字用户 ID 不会变。插件按数字用户 ID 认账号，所以改了 `@名` 不会把数据算到别人身上。即使某一刻没拿到 `@名`，只靠数字 ID 也能正常读取。
- 关闭按钮会写明要关闭的是哪个账号；关闭后保留本机数据，只是暂停该账号的功能和更新。

### 弹窗和两份数据

弹窗分「榜单」「设置」两页。设置页收口为「数据同步」（上半为「旁听收集 [别人回我]」与「旁听收集 [我回别人]」两行零请求开关及最近时间，下半为合二为一的「手动补读」自定义小时/天入口）、「页面显示」、「榜单口径与标签颜色」，以及底部默认折叠的「高级设置与说明」（统一收纳详细数据表、本机存储与清空、账号开关、口径与风险说明）；详细说明与精确读取/旁听摘要收在各旁的小问号里。

插件只处理两份回复数据：

| 数据 | 计入什么 | 不算什么 |
|---|---|---|
| **别人回我** | 根帖是我的，回复我的每一条，不分第几层 | 他在我帖子下回别人；他在别人帖子下回我；引用和普通 @ |
| **我回别人** | 我直接评论对方根帖的第一层，记在根帖作者名下 | 在他帖子下回别的评论者；他回我后我再回；我自己帖子下回别人的 |

「我回 N」只展示，不参与排名。只要本机已有任一「我回别人」记录（无论来自发帖实时旁听还是回复栏同步）或曾经同步过一次，榜单、标签和点开的明细就按当前窗口内已有记录直接显示（有啥显示啥）；完全没有记录且从未同步过时才显示「—」。

### 两个范围

- **手动补读范围**：设置页「数据同步 → 手动补读」，可自由调 **1–24 小时**或 **1–15 天**（打开弹窗时按最近旁听/读取时间自动预填建议时长）。只管点击手动补读时从当下往回读多远。
- **榜单范围**：榜单页左上，7 天到 3 个月。榜单、「我回 N」、时间线标签和汇总都按它算；改了只是重算，不读数据。
- 数据是攒出来的。就算从不手动补读，只靠日常「旁听收集」也能慢慢积累。榜单范围比本机数据长时照常显示，并注明最早只有哪天。

### 旁听收集和手动补读（原补历史与立即更新合二为一）

- **后台零定时主动请求**：日常不再在后台定时发 `fetch` 扫通知或回复栏，默认完全依靠浏览器自然浏览时的旁听收集（零额外网络请求、无时间窗口限制）。
- **旁听收集 [别人回我]**（默认开启）：你在电脑浏览 X「通知（全部）」「提及」「已认证」页时，自动按帖子编号去重写入回复并即时刷新榜单与标签。
- **旁听收集 [我回别人]**（默认开启）：你在电脑 Chrome 发送回复，或浏览本人个人主页「回复」栏时，自动按帖子编号去重写入并刷新榜单与标签（浏览他人主页自动跳过）。
- **统一「手动补读」**（`补读 [别人回我]` / `补读 [我回别人]`，各自独立 10 分钟冷却）：从当下往回按所选时长（`1–24 小时` / `1–15 天`）手动 `fetch` 一次，满足「到达所选时间边界」或「在连续覆盖区间内碰到上次接续点」谁先到即停。入站选 **≤ 24 小时**走轻量节奏（页间 4–28 秒、上限 48 页），选 **2–15 天**自动走慢速回填节奏（页间 15–110 秒、上限 220 页、支持暂停/继续）；出站统一沿用每轮 5 页、上限 225 页节奏。仅在 08:00–24:00 且 X 页面前台可见时执行。
- 扩展更新或重载后，会在白天自动刷新**各窗口当前前台**挂着旧内容脚本的 X 常规页面；后台页切回前台、跨窗口切回原窗口以及打开弹窗检测到未连接前台页时也会补刷，通知页绝不自动刷新，夜间顺延到次日处理。
- 两份主动任务共用读取锁，不会同时向 X 发请求。
- **账号异常硬熔断**：若任一手动请求收到 X 的账号异常、登录失效、验证/锁定、Cloudflare/HTML 挑战页或连续 3 次 429 限流信号（如 HTTP 401/403、错误码 32/64/89/226/326 或 `cf-mitigated`），插件会立即中止当前全部手动读取任务、清空所有待执行闹钟并在弹窗顶部红字告警；此后绝不自动恢复，需用户在 X 确认账号正常后再手动触发。

### 数据状态和时间显示

- 「数据同步」两行开关旁直接用灰色小字显示最近一次读取时间（如 `今天 18:27`）；点开对应小问号可看完整规则与精确到秒的本次扫描与新增条数（例如 `11/20 23:40:05 · 扫描 N 条 · 新增 M 条`）。
- 展开底部「高级设置与说明 → 数据详情」可查看两块数据各自的详细数据状态：本机条数、记录日期、上次补历史完成的时间和范围、上次成功读取的时间和本批条数；时间到分钟即可，例如 `11/20 23:40`。
- 各处使用紧凑格式并保持单行，弹窗宽度按这些字段调整过。

### 榜单、明细和导出

- 上榜条件：榜单范围内至少回复 `minCount` 次，再取前 `topN` 名。默认 2 次、前 100 名；次数相同按最近一次回复排序。
- 每行显示名次、头像、名字、`@ID`、最近一次回复时间、回复次数和「我回 N」。点头像去对方主页。
- 「我回 N」统计当前榜单窗口内本机已有的直接评论记录。本机记录没有覆盖整个窗口时也照常显示已有数字，并注明记录从哪天开始；从没读过或旧格式才显示「—」。
- 点这一行其他地方展开「他回我」「我回他」两栏，按榜单口径从新到旧排列，每栏最多显示最近 50 条。悬停时间可看方向、完整时间和本机保存的回复摘要；点击时间打开原帖。
- 可以按名字或 `@ID` 搜索。
- 「导出榜单」导出当前榜上的人；「导出全量数据」导出本机保存的全部统计相关记录，同一张 CSV 用「类型」列区分，并带是否计入榜单、摘要和链接。仅用于判定对话归属的 `own` 记录不导出。

### 时间线和通知标签

- **名次标签**：榜上的人名字旁显示名次、他回我的次数；「我回别人」读过之后再多一个「我回他几次」。颜色按回复次数分档，不按名次。鼠标悬停不再显示详情。
- **关系**：「互」是互关，「粉」是对方关注我而我没关注他，其他情况不标。页面上所有人都标，不限于榜上的人。
- **M**：只在通知列表里标，表示这条回复在我的帖子下。
- 名次、标签里的「我回他几次」、关系、M、发帖快捷档期各有显示开关；以后新增显示项也会配开关。
- 标签只读本机快照和 X 页面已经加载的数据，渲染时不额外发请求。

### 发帖排期快捷档期

- 在 X 原生排期弹窗里插入快捷档期条，只辅助填时间，不代点确认或发布。
- 每天 07:00–24:00 每 30 分钟一档（覆盖今天与明天，时间差跨天连续计算），归档区间为左闭右开 `[档位-15分, 档位+15分)`；已过去、距现在不足 10 分钟或距电脑端刚发原创/引用主帖不足 30 分钟（回复别人不触发）的档跳过。
- 前后硬性最小防撞间距为 **25 分钟**：档位内已有排期或夹缝不足 50 分钟凑不出安全分钟的档均置灰，悬停可看冲突排期时间与摘要。
- 顶部提供「← 上一档」「下一空档 →」快捷切换（无可用上一档/下一档时置灰）：点「下一空档 →」时，若前后夹着排期且空隙在 50–80 分钟内（如正好差 1 小时）自动取中点 ±1–3 分钟均匀居中，其余落在前一条后 30–40 分钟；点下方具体半小时档位时仅做 ±1–3 分钟小幅浮动（贴近所选时间并满足 25 分钟安全间距）。
- 选定时间后，顶部以单行三段式时间轴展示「上一条（或刚发）— 间隔 — 本条 — 间隔 — 下一条」（哪一侧无排期则淡灰显示「无」）。
- 每次打开排期弹窗先显示本机缓存，再按需读取一次最新排期（30 秒防抖）。第一次需要在 X 点一次「已排期帖子」让插件记下读取方式；遇到限流或服务错误会进入退避期，不因反复打开弹窗重复发请求。

### 分享菜单「复制原文」

- 点任意推文底部的分享按钮打开分享菜单时，会在「复制链接」下方自动增加「复制原文」（零额外请求、无独立开关）。
- 优先从当前页面旁听内存直接复制完整原文：折叠长推文无需先点「显示更多」，正文中的 `t.co` 外链自动还原为真实 URL，附带的图片/视频/动图自动附带具体媒体直链；未命中旁听内存时自动回退解析页面 DOM（保留 Emoji、不混入引用帖正文）。

### 设置

- **榜单口径**：名次上限和最少回复次数可调。恢复默认只恢复这两个值、颜色和门槛，不动数据。
- **标签颜色**：默认 ≥20 次红、10–19 次橙、5–9 次蓝、其余灰。每档门槛和颜色可改，可加档或删档，最多 4 个门槛档加 1 个兜底色。
- **本机存储**：显示两份数据合计条数、插件占用和保存期限。
- **清空数据**：按账号清掉两份回复、读取进度和排期缓存，账号绑定和设置保留，不能恢复。

### 本机保存与清理

- 两份数据都只保留最近 90 天；更早的每天最多清一次。
- 最早的数据存满 80 天时，榜单上方红字提示先导出；第一次清理之后改成一行小字说明。
- 一条回复约 300–500 字节；一周一万条回复的量级，90 天约 50 MB。

### 后台诊断日志

- 本机静默保留最近 7 天的全量诊断日志（含请求状态、分页停止原因、跨窗口刷页与发帖旁听命中记录等），弹窗界面不再占用查看或回查入口。
- 维护阶段可通过本机数据桥将 `.local/` 日志与数据直连交给 AI 排查问题，无需手动导出或复现。

### 为什么必须开着 X 页面

请求必须从已登录的 x.com 页面里发出，才能同源、带当前网页会话，所以插件不需要 `cookies` 权限，也不能脱离页面在后台直接读 X。

Chrome 会随时回收扩展的后台 Service Worker。插件不靠内存里的定时器，而是把进度写在本机、用 `chrome.alarms` 闹钟续跑；因此关掉浏览器、没有 X 页面或电脑休眠时只是暂停，条件恢复后接着读。

页面变化时，内容脚本只在本机重新扫描用户名节点并更新标签，不发网络请求；自己插入标签引起的变化会排除，避免反复扫描。

## 风险提示

日常收集完全依赖 X 页面自然加载时的旁听（只看不改、零额外请求）。手动点击「立即更新」或「补历史」时用的是 X 网页版的内部只读接口，不是官方 API，属于服务条款的灰色地带，可能导致账号被限流。插件已彻底关闭后台定时自动抓接口，主动读取只在本地时间 08:00–24:00 且 X 页面前台显示时按需手动发生，只读、低频，不做点赞、关注或发帖；打开排期弹窗时仍会按需同步一次已排期列表（同样只在工作时段、X 页面前台显示时发请求，否则只用缓存）。数据只存在本机，不上传、不上报，风险无法保证为零。

## 代码结构

| 文件 / 目录 | 职责 |
|---|---|
| `src/x/fetcher.js` | 抓取层：接口路径、参数和请求头。读提及、我的回复列表和已排期列表，返回原始 JSON |
| `src/x/parser.js` | 解析层：提及、我的回复、`CreateTweet` 旁听与已排期列表 → 统计事件与翻页游标；结构不符抛错 |
| `src/x/mentions-diagnostics.js` | 提及诊断：裁剪请求条件和响应结构，不保存完整地址、游标或正文 |
| `src/content/tap.js` | 页面脚本环境里的旁听层：只做请求/返回的路由，不做统计业务，不发请求、不改页面 |
| `src/content/rel.js` | 从旁听数据里取关注关系、帖子归属、读取模板、`CreateTweet` 与排期事件，只放页面内存或交给后台 |
| `src/content/schedule.js` | 发帖排期的纯逻辑：半小时档位、25 分钟硬防撞、中点均分 / 30–40 分钟顺排、具体档 ±1–3 分钟微调与前后参考时间差 |
| `src/content/schedule-ui.js` | 在 X 原生排期弹窗里画快捷档期并填入原生下拉框 |
| `src/content/content.js` | 账号识别、代后台发请求、注入名次/关系/M 标签。页面选择器集中在顶部 `SEL` |
| `src/background.js` + `src/bg/` | 后台 Service Worker 入口与领域模块：补历史、增量、出站旁听/同步、排期、退避、账号隔离、跨窗口刷新、消息路由 |
| `src/rank.js` | 纯函数：统计口径、榜单、标签快照、颜色分档和规则合法化 |
| `src/db.js` | IndexedDB 和 `chrome.storage.local` 键名 |
| `src/diagnostics.js` | 诊断日志写入、读取和 7 天过期清理 |
| `src/ui/` | 弹窗界面与纯逻辑辅助（`popup.js` / `popup-helpers.js`） |

隔离原则：只有 `fetcher.js`、`parser.js`、`mentions-diagnostics.js` 知道主动请求的 X 接口字段，只有 `content.js` 和 `schedule-ui.js` 知道 X 页面选择器。`tap.js` 与 `rel.js` 是明确例外，只做旁听路由和内存解析，不发请求、不落候选数据。其他文件不直接依赖 X 的 DOM 或接口结构。
