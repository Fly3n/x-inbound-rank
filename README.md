# X 友（Chrome 插件）

统计谁最常在我的 X 帖子下回复我，给回复者排名，并在时间线和评论区的用户名旁标出名次和次数；榜单里还能看到我在对方帖子下直接回复了几次。数据只存本机，不上传。

- 功能和要求以 [REQUIREMENTS.md](REQUIREMENTS.md) 为唯一出处。
- 技术事实、数据模型和维护约束见 [AGENTS.md](AGENTS.md)。
- 当前版本和每版改动见 [CHANGELOG.md](CHANGELOG.md)，弹窗标题旁也显示版本号。

## 安装

1. Chrome 打开 `chrome://extensions`，右上角打开「开发者模式」。
2. 点「加载已解压的扩展程序」，选本目录（含 `manifest.json` 的这一层）。
3. 刷新已经打开的 x.com 标签页；安装前打开的页面里没有内容脚本。

改了代码后，在扩展页点刷新，再刷新 x.com 页面。不需要打包，也不上架商店。

## 第一次使用

1. 装好后刷新 x.com，在要使用的 X 账号页面点插件图标，再点「为此账号开启」。
2. 设置页「数据读取」保持默认的 7 天，先点「别人回我」那一块的「初始化」；「我回别人」也点一次。
3. 一两分钟后看弹窗：显示「进行中，本轮已读 N 页」说明接口和解析对上了；显示红色错误就把提示原样交给维护者，不要反复重试。
4. 打开一条有人回复过你的帖子，看用户名旁是否出现名次和次数标签。
5. 想看更早的数据，把初始化范围改成 15 天或 30 天，再点「初始化」。之后两份数据会按小时积累，榜单最多能看 3 个月。

## 使用

### 账号

- 可同时开启多个 X 账号。回复、榜单、设置、排期缓存和诊断日志各自独立；某个账号没有登录页面时，只暂停它自己的任务。
- X 的每个账号有两个名字：页面上的 `@用户名` 可以改；后台的数字用户 ID 不会变。插件按数字用户 ID 认账号，所以改了 `@名` 不会把数据算到别人身上。即使某一刻没拿到 `@名`，只靠数字 ID 也能正常读取。
- 关闭按钮会写明要关闭的是哪个账号；关闭后保留本机数据，只是暂停该账号的功能和更新。

### 弹窗和两份数据

弹窗分「榜单」「设置」两页。设置页从上到下是数据读取、时间线和发帖时显示什么、榜单口径、标签颜色，最后是默认折叠的风险说明、诊断日志和清空数据。功能旁的小问号点开才显示说明；两份回复的数据状态直接显示，不用再展开。

插件只读两份回复数据：

| 数据 | 计入什么 | 不算什么 |
|---|---|---|
| **别人回我** | 根帖是我的，回复我的每一条，不分第几层 | 他在我帖子下回别人；他在别人帖子下回我；引用和普通 @ |
| **我回别人** | 我直接评论对方根帖的第一层，记在根帖作者名下 | 在他帖子下回别的评论者；他回我后我再回；我自己帖子下回别人的 |

「我回 N」只展示，不参与排名。「我回别人」第一次读完之前，榜单、标签和点开的明细都不显示这项，避免把没完成的数据当成完整结果。

### 两个范围

- **初始化范围**：设置页「数据读取」，7 天、15 天、30 天。只管点「初始化」时往回读多远。
- **榜单范围**：榜单页左上，7 天到 3 个月。榜单、「我回 N」、时间线标签和汇总都按它算；改了只是重算，不读数据。
- 数据是攒出来的。初始化 7 天、用一个月后，本机就有一个多月的数据。榜单范围比本机数据长时照常显示，并注明最早只有哪天。

### 初始化

- 两份数据各有一个「初始化」按钮，第一次必须手动点；没初始化过不会自动读。
- 每次从最新一条往回读到所选初始化范围的起点。已有记录不删、不重复计数，所以先读 7 天再改成 30 天，会重新走一遍但只补缺的部分。
- 本机数据已经覆盖所选范围时按钮置灰，旁边说明原因。
- 读取期间按钮立即锁定，显示排队、进行中、等待 X 页面或等待回复页；榜单和时间线标签显示已经读到的数据。
- 「我回别人」如果 X 的列表先到底，或单次读取达到页数上限，不会把这次读取当成已覆盖所选范围。界面会显示实际最早读到哪天；达到上限后自动更新不再重试，可以重新初始化或缩小范围。

### 自动更新和立即更新

- 「自动更新两份数据（约每小时）」只控制「别人回我」「我回别人」两份回复数据，不控制发帖排期的按需同步。
- 初始化完成后约每小时更新一次，间隔在 50–70 分钟之间随机，不卡整点。每次从最新往回读，并在上次位置之外多看最近 24 小时；只有该账号的 X 页面开着时才执行。
- 重叠读到的回复按帖子编号只存一份，不会重复计数。X 有时会晚十几分钟才把回复放进「提及」列表，后续更新会自动补上；「已读 N / 新增 0」只表示这次读到的本机都有了，不代表没有新回复。
- 一轮最多读 40 页。关机一整天之类读满还没接上时，会记下位置，休息一两分钟后放慢速度接着读，直到接上或读到保存期限，不会丢下这一段。
- 「立即更新」触发已初始化的两路增量，不受普通定时间隔限制，但仍遵守分页节奏、串行读取和接口退避。
- 两份数据共用同一个读取锁，不会同时向 X 发请求。关掉自动更新后，正在跑的两份数据任务会暂停。

### 数据状态和时间显示

- 顶部摘要每行是「别人回我：」或「我回别人：」加读取时间、本批读到和新增的条数。时间显示到秒，例如 `11/20 23:40:05`，不显示年份。
- 两块数据各自的「数据状态」直接显示本机条数、记录日期、上次初始化完成的时间和范围、上次成功读取的时间和本批条数；时间到分钟即可，例如 `11/20 23:40`。
- 各处使用紧凑格式并保持单行，弹窗宽度按这些字段调整过。

### 榜单、明细和导出

- 上榜条件：榜单范围内至少回复 `minCount` 次，再取前 `topN` 名。默认 2 次、前 100 名；次数相同按最近一次回复排序。
- 每行显示名次、头像、名字、`@ID`、最近一次回复时间、回复次数和「我回 N」。点头像去对方主页。
- 点这一行其他地方展开「他回我」「我回他」两栏，按榜单口径从新到旧排列。悬停时间可看方向、完整时间和本机保存的回复摘要；点击时间打开原帖。
- 可以按名字或 `@ID` 搜索。
- 「导出榜单」导出当前榜上的人；「导出全量数据」导出本机两份数据的每一条，同一张 CSV 用「类型」列区分，并带是否计入榜单、摘要和链接。

### 时间线和通知标签

- **名次标签**：榜上的人名字旁显示名次、他回我的次数；「我回别人」读过之后再多一个「我回他几次」。颜色按回复次数分档，不按名次。
- **关系**：「互」是互关，「粉」是对方关注我而我没关注他，其他情况不标。页面上所有人都标，不限于榜上的人。
- **M**：只在通知列表里标，表示这条回复在我的帖子下。
- 名次、标签里的「我回他几次」、关系、M、发帖快捷档期各有显示开关；以后新增显示项也会配开关。
- 标签只读本机快照和 X 页面已经加载的数据，渲染时不额外发请求。

### 发帖排期快捷档期

- 在 X 原生排期弹窗里插入快捷档期条，只辅助填时间，不代点确认或发布。
- 每天 07:00–24:00 每 30 分钟一档。已过去、距现在不足 10 分钟或距最近发帖不足 15 分钟的档跳过。
- 每档前后 15 分钟内已有排期就置灰；悬停可看已排时间和正文摘要。
- 横排显示当天最近的几个档，其余今天档位和明天全天收在「更多档期」里。
- 点击空档后随机前后浮动 1–6 分钟，填入 X 原生日期/时间下拉框；最后一步仍由用户点。
- 每次打开排期弹窗先显示本机缓存，再按需读取一次最新排期（30 秒防抖）。第一次需要在 X 点一次「已排期帖子」让插件记下读取方式。

### 设置

- **榜单口径**：名次上限和最少回复次数可调。恢复默认只恢复这两个值、颜色和门槛，不动数据。
- **标签颜色**：默认 ≥20 次红、10–19 次橙、5–9 次蓝、其余灰。每档门槛和颜色可改，可加档或删档，最多 4 个门槛档加 1 个兜底色。
- **本机存储**：显示两份数据合计条数、插件占用和保存期限。
- **清空数据**：按账号清掉两份回复、读取进度和排期缓存，账号绑定和设置保留，不能恢复。

### 本机保存与清理

- 两份数据都只保留最近 90 天；更早的每天最多清一次。
- 最早的数据存满 80 天时，榜单上方红字提示先导出；第一次清理之后改成一行小字说明。
- 一条回复约 300–500 字节；一周一万条回复的量级，90 天约 50 MB。

### 诊断日志

- 本机保留最近 7 天的全量诊断日志，不抽样。弹窗显示最近 10 条，可以导出该账号的全部。
- 日志包含浏览器环境、扩展版本、读取批次、请求条件摘要、HTTP 状态、分页、重试、帖子编号和解析、入库判定，用于对照漏收、响应过旧或接口变化。
- 导出会移除账号标识，不包含凭证、完整请求地址或正文；但帖子编号可能关联公开帖子，分享前请先检查。
- 「按时间回查别人回我」会从最新提及往前查，单次最多 20 页，可选择最近 1、6、24 小时或自定义时间；回查只读并写诊断，不动增量接续点和榜单数据。

### 为什么必须开着 X 页面

请求必须从已登录的 x.com 页面里发出，才能同源、带当前网页会话，所以插件不需要 `cookies` 权限，也不能脱离页面在后台直接读 X。

Chrome 会随时回收扩展的后台 Service Worker。插件不靠内存里的定时器，而是把进度写在本机、用 `chrome.alarms` 闹钟续跑；因此关掉浏览器、没有 X 页面或电脑休眠时只是暂停，条件恢复后接着读。

页面变化时，内容脚本只在本机重新扫描用户名节点并更新标签，不发网络请求；自己插入标签引起的变化会排除，避免反复扫描。

## 风险提示

读取用的是 X 网页版的内部接口，不是官方 API，属于服务条款的灰色地带，可能导致账号被限流。关系标签需要在 X 页面里旁听它自己加载的数据（只看不改）。插件只读、低频，不做点赞、关注或发帖。关掉「自动更新」后不再自动更新两份回复数据，但打开排期弹窗时仍会按需读取一次已排期列表。数据只存在本机，不上传、不上报，风险自担。

## 代码结构

| 文件 | 职责 |
|---|---|
| `src/x/fetcher.js` | 抓取层：接口路径、参数和请求头。读提及、我的回复列表和已排期列表，返回原始 JSON |
| `src/x/parser.js` | 解析层：提及和我的回复列表 → 统计事件与翻页游标；结构不符抛 `ParseError` |
| `src/x/mentions-diagnostics.js` | 提及诊断：裁剪请求条件和响应结构，不保存完整地址、游标或正文 |
| `src/content/tap.js` | 页面脚本环境里的旁听层：只转发 X 自己发出的相关请求和返回，不发请求、不改页面 |
| `src/content/rel.js` | 从旁听数据里取关注关系、帖子归属、读取模板和排期事件，只放页面内存或交给后台 |
| `src/content/schedule.js` | 发帖排期的纯逻辑：半小时档位、±15 分钟冲突、随机浮动 |
| `src/content/schedule-ui.js` | 在 X 原生排期弹窗里画快捷档期并填入原生下拉框 |
| `src/content/content.js` | 账号识别、代后台发请求、注入名次/关系/M 标签。页面选择器集中在顶部 `SEL` |
| `src/background.js` | 调度：初始化、自动更新、限流退避、账号隔离、消息处理。节奏参数集中在顶部 `PACE` |
| `src/rank.js` | 纯函数：统计口径、榜单、标签快照、颜色分档和规则合法化 |
| `src/db.js` | IndexedDB 和 `chrome.storage.local` 键名 |
| `src/diagnostics.js` | 诊断日志写入、读取和 7 天过期清理 |
| `src/ui/` | 弹窗界面 |

隔离原则：只有 `fetcher.js` 和 `parser.js` 知道 X 接口字段，只有 `content.js` 和 `schedule-ui.js` 知道 X 页面选择器。其他文件不直接依赖 X 的 DOM 或接口结构。

## 测试

`fake-indexeddb` 只是测试依赖，插件本身零依赖、无需构建。

```bash
npm install
npm test
```

- `test/logic.test.mjs`：榜单、统计口径、规则合法化、颜色、解析边界、账号只有数字 ID 的情况。
- `test/flow.test.mjs`：用假 chrome API 和假接口跑后台全流程，包括初始化、429 退避、续跑、去重、增量、开关、我回别人覆盖状态、诊断和清空。
- `test/db.test.mjs`：重复写入的合并规则，空值不覆盖已知的根帖归属、正文和头像。
- `test/session.test.mjs`：账号会话切换和页面缓存隔离。

假数据按预期接口形态写成，能证明逻辑自洽，不能证明 X 当前真实返回一定长这样。弹窗和排期界面没有自动测试，改完要在 Chrome 里实际看一眼。

## 实测与现状

- 2026-11-14 起在负责人的真实账号上运行，读取回复、榜单和名次标签可用；负责人以体验反馈为准，不做逐条人工核对。
- 2026-11-21 实测到 X 的提及列表会短时滞后十几分钟：回复已经发出，接口仍返回旧首页；X 自己刷新后，插件用同一接口补回。0.24.0 起更新会额外回看最近 24 小时。
- 2026-11-19 用小号确认：提及的旧 REST 接口仍可用（180 次 / 15 分钟）；网页版自用的 GraphQL 提及接口可用（1500 次 / 15 分钟、每页 40 条）；「回复」栏接口照页面模板重发可用，额度 50 次 / 15 分钟，返回结构能解析。
- 「我回别人」的深层回复不一定带根帖，只有约一半能可靠认出根帖主人，所以只统计第一层。
- 关系/M 旁听、发帖排期快捷档期、多账号隔离、全量诊断已实现，等待真实使用反馈。
- 尚未确认：提及列表能往回翻多深、长时间运行的账号行为风控边界、X 改版后的页面结构和接口变化。读不了时插件会在弹窗报错，不会静默拿旧数据冒充完整。

接口会变。X 改版后如果读取失败或标签消失，把弹窗里的原样提示交给维护者。
