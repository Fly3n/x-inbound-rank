# 产品说明书（唯一产品事实源）

这份文档是「X 友」产品决策的唯一出处。仓库中的功能、口径、风控底线和界面行为均以此为准；代码与文档发生偏差时，先对齐这里再改代码。技术实现与接口实测详见同目录其他文档。

---

## 第一层：需求层

### 定位
- 开源、自用的 Chrome 浏览器插件，帮 X 账号运营者直观识别高互动好友。
- 所有互动数据仅保存在本机浏览器，不上传、不联网上报、不收费。
- 维护阶段提供本机回环数据桥（数据与日志自动落在本机仓库 `.local/` 目录），方便开发者和 AI 直接定位问题，无需反复手动导出或复现；该通道属于维护工具，正式分发前剥离临时本地权限。

### 核心能力
1. **双向回复统计与榜单**：统计「谁最常在我的帖子下回复我」并生成回复榜，顺带展示「我直接评论了对方几次」，支持搜索、展开双向明细与本地导出 CSV。
2. **页面内联标签**：在 X 时间线、评论区与通知列表的用户名旁直接标出名次与次数、互关/粉丝关系，以及通知是否属于我的帖子下。
3. **多账号隔离与可排查性**：多个 X 账号各自独立启用、独立存储与调度；后台静默记录最近 7 天全量诊断日志，便于按结果和日志定位异常。

### 延后与不做
- **延后项**：发帖排期快捷档期（当前保留现有可用形态，本轮不作改动，后续单独规划）。
- **明确不做**：
  - 不统计引用、点赞、转发，不做综合榜；不做时间衰减，不给「我回他」加分。
  - 绝不代点点赞、关注、发帖或排期确认，绝不自动打开 X 通知页（避免改动未读状态）。
  - 不做固定或常驻独立弹窗；不做无明确故障原因的重复全量回扫。

## 第二层：规则层

### 1. 固定优先级（冲突时严格按顺序取舍）
**账号安全 > 数据完整与正确 > 轻量低噪声 > 及时性**
宁可新回复晚半天或次日才出现，也绝不为了追求实时性增加请求频率。

### 2. 双向统计口径
| 方向 | 计入统计 | 不计入 |
|---|---|---|
| **别人回我**（决定排名） | 根帖是我的，对方直接回复我的**每一条**（不分层；仅用当次提及返回与本机已有对话记录旁证归属，**零二次请求**） | 他在我帖子下回别人；他在别人或他自己帖子下回我；引用、普通 @ |
| **我回别人**（仅展示「我回 N」，不加分） | 我直接评论对方根帖的**第一层**，记在根帖作者名下（**零二次请求**） | 深层回复（回他帖下评论、他回我后我再回）；我在自己帖子下回别人 |

- 表内保留完整抓到的回复，是否计入榜单只在计算时判定，调整口径无需重抓。

### 3. 显示原则
- **有啥显示啥**：榜单、明细与标签按当前选定的榜单范围直接聚合本机已有数据；不因为历史补读未覆盖满整个周期而把已读到的「我回 N」藏成空白或横杠。
- 仅在完全没有任何「我回别人」记录且从未同步过时，才显示「—」，避免把未开启/未读取误解为「一次没回」。

### 4. 两个范围解耦
- **手动补读范围**：支持用户自定义 **1–24 小时**或 **1–15 天**（从当下往回读取，上限 15 天），打开弹窗时按本机最近一次旁听/读取时间自动预填建议时长，随时可改。
- **榜单范围**：**7 天 / 半个月 / 1 个月 / 2 个月 / 3 个月**，控制榜单、「我回 N」、时间线标签和汇总；切换只重算本机数据，不发任何请求。
- 本机数据少于所选榜单范围时照常计算显示，并轻标最早仅有哪天的数据。

### 5. 抓取机制与风控底线
- **彻底取消后台定时主动抓取（日常纯旁听、按需统一手动补读）**：
  - 后台**不再**发起任何定时自动 `fetch`；`chrome.alarms` 仅保留 30 分钟本地维护任务（清理过期数据、重算快照、推送本机桥）与恢复用户手动发起但未跑完的续读任务。
  - 原「补历史」与「立即更新」合二为一为统一的**「手动补读」**（仅在用户主动点击时从当下往回 `fetch`，不点则零主动请求）；按钮不再因「曾补过历史」而置灰锁死，仅在任务进行中或 10 分钟独立冷却内限制重复点击。
- **别人回我（默认旁听收集 + 可选手动补读）**：
  - **旁听收集 [别人回我]**（`tapInEnabled`，默认开启）：用户自己在 Chrome 浏览 X「通知（全部）」「提及」「已认证」页时，插件直接旁听页面收到的 `NotificationsTimeline` 响应，将其中别人对我的直接回复按帖子编号去重写入本机并即时刷新榜单与标签（**0 主动请求**，无时间窗口限制，不推进 `syncedId`）；后台全程记录旁听诊断日志并实时同步到本机数据桥。关闭此开关即停止入站旁听写入。
  - **手动补读 [别人回我]**：仅在本地时间 **08:00–24:00** 且同账号 X 页面**正在前台显示**时发请求；按用户所选时长（`1–24 小时` 或 `1–15 天`）从当下往回翻页，满足**「到达所选时间边界」或「在连续覆盖区间内碰到上次 `syncedId`」谁先到即停**（避免长时间纯旁听后去追陈旧接续点，也避免重复翻已连续覆盖的段落）。所选时长 **≤ 24 小时**自动走轻量节奏（页间 4–28 秒平滑随机、每 6 页休 3–5 分钟、单轮上限 48 页）；**2–15 天**自动走慢速回填节奏（页间 15–110 秒、每 8–12 页休 3–5 分钟、单次上限 220 页，支持暂停/继续）。仅使用网页版现行 GraphQL `NotificationsTimeline` 模板，模板缺失或过期时提示用户自行打开一次 X 通知页重连，不再降级请求已废弃的旧 REST `mentions.json`。
- **我回别人（默认旁听收集 + 可选手动补读）**：
  - **旁听收集 [我回别人]**（`tapOutEnabled`，默认开启）：正常人在 Chrome 里发回复（`CreateTweet`），或自己浏览本人个人主页「回复」栏（`UserRepliesTimeline` / `UserTweetsAndReplies`）时，通过页面旁听实时记录入库（**0 主动请求**，按帖子编号去重，深层与自帖回复照常识别并用作旁证，不碰 `cur.out` 同步游标）；浏览他人主页回复栏时不触发入库。关闭此开关即停止出站回复旁听写入（不影响发帖排期的主帖缓冲时间）。
  - **手动补读 [我回别人]**：与入站共用「手动补读」时长选择（`1–24 小时` / `1–15 天`）与独立 10 分钟冷却，同样按「到达所选时间边界」或「连续覆盖区间内碰到上次 `out.syncedId`」谁先到即停，沿用 50 次/15 分钟严苛额度节奏（每轮 5 页、休 3–5 分钟、上限 225 页 / 45 轮）。
- **通用风控、串行与异常守则**：
  - 全程只读 GET；正式功能仅申请存储、闹钟与 X 站点权限，绝不加 `cookies`、`tabs`、`scripting`。
  - 按 X 后台数字用户 ID 隔离多账号，改 `@用户名` 不丢归属；未开启账号零采集、零标签、零请求。
  - 三条数据底线：**同一帖子编号只算一次**、**新响应空值不覆盖已知事实**、**任务中断可续读**。
  - 全局同一时刻最多跑 1 个主动读取动作；读取期间禁止清空数据。
  - 账号级限流退避：任一主动入口触发 429，整个账号所有主动入口统一暂停（取 X 重置时间与「15 分钟起翻倍、上限 4 小时」中较长者，到期成功读取后清零）；**连续 3 次 429 直接升级为账号异常硬熔断**；502/503/504 临时错误逐次退避重试，**连续最多 3 次**，超限即中止任务并清掉闹钟与续读进度，避免无限重打。
  - **账号异常硬熔断（半开探测恢复）**：异常检测优先于 429 退避执行；任一主动请求收到 HTTP 401/403、连续 3 次 429、`cf-mitigated`、挑战/登录重定向（`/account/access`、`/i/flow/`、`/login`）、非 5xx HTML 挑战页或带强挑战特征（Cloudflare/Arkose）的 503 页，或 X 返回账号封禁/锁定/要求验证/判定自动化等异常信号（错误码 32/64/89/226/326、`Bounce` 或锁定限制提示），立即中止当前全部手动读取任务、清空全部待执行闹钟与续读进度并在弹窗顶部挂红字告警；熔断后**绝不自动恢复**。用户确认账号正常后再次手动触发读取时采用**半开探测**：不在发请求前预先清除熔断，仅放行当次首屏探测请求，**只有收到 X 正常响应（`ok`）后才真正解除 `circuitBroken` 与告警**；若被夜间窗口、退避期挡下或探测再次失败，熔断标记保持不解除。
  - 两路「立即更新」彼此独立，各自有 10 分钟冷却并共享全局串行与账号级限流退避；手动更新与补历史不受「旁听收集」开关影响。
  - 异常必须可见：重复游标、接上旧位置前提前空页/无下一页、结构未知或作者 ID 缺失时立即报错，**绝不推进接续点或冒充完整覆盖**；单条已删除/受保护回复跳过不拖垮整页。
  - 90 天留存：两份数据仅保留最近 90 天（每天最多清理一次）；最早数据存满 80 天且未清理过时红字预警先导出，首次清理后改成一行灰字提示。

## 第三层：细节层

### 1. 弹窗界面与导出
- 分「榜单」「设置」两页（无数据时默认落设置页，点击弹窗外部自动关闭）；所有功能说明收进控件旁的小问号按钮里。
- 榜单页：支持按名字/`@ID` 搜索；上榜门槛 `minCount`（默认 2，范围 1–99）与上限 `topN`（默认 100，范围 10–500），同次数按最近回复排；行内仅头像是主页链接，点击其余位置展开「他回我」「我回他」各最近 50 条时间明细，点时间打开原帖。
- 设置页按功能收口为 3 张主卡片 + 底部统一折叠的「高级设置与说明」区（原顶部「补历史」折叠卡与「立即更新」已合并进「数据同步」）：
  - 首张卡片「数据同步」分为上半「旁听收集」（`旁听收集 [别人回我]` 与 `旁听收集 [我回别人]` 两行开关，各自配行内灰色小字最近时间与 `?` 精确读取/旁听摘要）与下半「手动补读（从当下往前）」（按本机最近同步时间自动预填建议时长、支持用户自由调整 `1–24 小时` 或 `1–15 天`，配独立 `补读 [别人回我]` / `补读 [我回别人]` 按钮及进行中的暂停/继续控件）。
  - 其下为「页面显示」（5 个标签与排期开关）、「榜单口径与标签颜色」（门槛、上限、分档配色预览与恢复默认）。
  - 「高级设置与说明」默认折叠，内部分块收纳「数据详情（两份详细数据状态表）」「本机存储与清空数据」「账号管理」与「口径与风险说明」。
- 导出：保留榜单页右上角单一「导出」入口，本地生成带 BOM 的 CSV，分「导出榜单」与「导出全量数据」（带「类型」与「是否计入统计」列，不导出仅作旁证的 `own` 记录），沿用现行字段结构。
- **精简诊断界面**：弹窗内不再放「按时间回查」表单和「查看/导出日志」面板；后台继续全量静默记录最近 7 天诊断日志并随本机数据桥自动落入 `.local/`。

### 2. 页面内联标签（渲染零额外请求）
- **名次标签**：仅对榜上人显示「名次 + 他回我次数 +（已有出站数据时）我回他次数」；按回复次数分档配色（默认 ≥20 红、10–19 橙、5–9 蓝、其余灰；最多 4 门槛 + 1 兜底色共 8 色可选，固定实心底色不随 X 主题变）；不显示悬浮详情。
- **关系标签**：「互」（互关）、「粉」（他关我、我未关他），全站非本人用户都标，仅读页面旁听内存。
- **归属标签**：「M」仅在通知列表里标属于我帖子下的回复。
- 名次、名次里的我回他、关系、M 与发帖排期各有独立显示开关。

### 3. 扩展重载自动刷新旧页面
- 扩展重载或更新后，仅在白天 08:00–24:00 且至少存在已启用且未熔断的账号时，自动刷新**各窗口当前前台**挂着旧版本脚本的常规 X 页面（包含跨窗口切回 X 窗口时的补刷；打开弹窗检测到当前前台为未连接的常规 X 页面时也会立即补刷）；后台标签页不强刷，通知页、发帖页（`/compose`）、登录/登出/挑战/设置页（`/account/access`、`/i/flow/`、`/login`、`/logout`、`/settings`）及已熔断账号绝不自动刷新；同一标签页 5 分钟内最多自动刷新一次，防止离线或验证页陷入循环刷新。

### 4. 发帖排期快捷档期（纯旁听与本地增量维护，零主动请求）
- 07:00–24:00 每半小时一档（覆盖今天与明天，时间对比跨天连续计算），归档区间为左闭右开 `[档位-15分, 档位+15分)`；前后硬性最小安全防撞间距均为 **25 分钟**（夹缝不足 50 分钟的档自动置灰）。
- 两种选点动作区分处理：点「下一空档 →」时，若前后均夹着排期且空隙在 50–80 分钟内，取正中点 ±1–3 分钟均匀居中，否则落在前一条之后 30–40 分钟；点具体时间档时仅做 ±1–3 分钟小幅浮动（避开整点/半点），若距邻近排期不足 25 分钟再就近微调。
- **纯旁听维护与已发排期留存（0 主动请求）**：
  - 打开排期弹窗全程**不发起任何主动请求**，直接读取本机排期缓存；也不再捕获排期请求模板或提供手动刷新按钮。
  - 旁听电脑端新建排期（`CreateScheduledTweet`）与删除排期（`DeleteScheduledTweet`）自动增量更新本机列表；用户自行打开 X 原生「已排期帖子」时旁听 `FetchScheduledTweets` 做全量校准对齐。
  - 已到点自动发出的排期在本地保留最近 **24 小时**（全量校准时也不抹除，仅用户主动删除才移除），与电脑端刚发的原创/引用主帖（不含回复评论）共同参与 **30 分钟首档顺延**、**25 分钟防撞**及三段式时间轴的「上一条」计算。
- 顶部提供「← 上一档」「下一空档 →」快捷切换（无可用上一档/下一档时置灰），下方保留横排近期档位与「更多档期」下拉；选定时间后以单行三段式时间轴展示「上一条（或刚发/已发）— 间隔 — 本条 — 间隔 — 下一条」（无对应排期一侧淡灰显示「无」）；只自动填入原生表单，绝不代点确认发布。

### 5. 分享菜单「复制原文」（常开轻量增强，零请求、无独立开关）
- 点击任意推文底部操作栏的分享按钮打开原生分享菜单时，在「复制链接」下方自动插入一个原生样式的「复制原文」菜单项，不设独立设置开关、不新增任何权限、不发起任何网络请求。
- 复制内容仅包含该条推文正文（不含作者名、时间、本帖链接，也不混拼引用帖正文），优先从当前页面旁听内存（`rel.js`）按帖子 ID 取出完整原文：
  - 折叠长推文（`note_tweet`）直接复制完整全文，无需先点「显示更多」；
  - 正文中的 `t.co` 外链自动还原为真实展开 URL（含引用帖链接）；
  - 附带图片/视频/动图的媒体短链（或长文附件）转为具体媒体直链（图片取 `media_url_https`，视频/动图取最高码率 `video/mp4`，拿不到时退回 `expanded_url`），多条按行排列；
  - 还原 HTML 转义字符（`&amp;` / `&lt;` / `&gt;`），并跳过回复帖隐藏的前置 `@用户名`。
- 若旁听内存里尚无该条推文（如首屏静态内容或未启用账号页面），自动回退解析该条推文顶层 DOM（还原 Emoji `<img alt>`、排除嵌套引用帖、附带页面可见图片链接）；复制完成后关闭菜单并展示轻提示。
